# ACEAPEX 2.4.1 — 2026-10-28

Build fixes for Windows (MinGW), gcc 9/10 and 32-bit ARMv5, found by the lzbench CI (#355). Nothing else changes: format, archive bytes, encoders and decoders are those of 2.4.0
(`release/v2.4.0.md`).

- `aceapex_main.cpp` used `pread` in the CLI's streaming paths (`d --out -`, the `faidx` index build). MinGW has no
  `pread`, so the library did not compile on Windows since 2.3.0, also inside lzbench (lzbench #355, four MinGW jobs).
  Positional reads now go through `ax_pread`: POSIX `pread`; on Windows `ReadFile` with an OVERLAPPED offset; 64-bit
  offsets; `O_BINARY` on those opens.
- gcc 9/10: `_mm256_cvtsi256_si32` (gcc 11+) replaced by `_mm_cvtsi128_si32(_mm256_castsi256_si128(x))`, the same instruction.
- 32-bit ARMv5: a 64-bit atomic counter in the fast profile's range batch (no lock-free form there, unresolved
  `__atomic_load_8`) is `size_t` now.
- Checked: the lzbench wrapper compiles with MinGW-w64 x86_64 and i686, gcc 10, gcc 13, clang, arm-linux-gnueabi (no `__atomic_*_8` left); Linux pipe test 36/36,
  conformance 27/27, streaming decode of a default and a fast archive, `faidx`, bit-perfect.
