# ACEAPEX 2.6.1 — 2026-11-03

Fixes from the lzbench review of 2.6.0 (inikep/lzbench#357) and a big-endian fast profile. Format unchanged: on x86
every archive of levels 1-3 and 11-18 is byte-identical to 2.6.0 (silesia, enwik8, chr1 at 1 and 4 threads: 66/66).

- **Decoder thread budget**: `aceapex_decompress_mt(threads)` keeps at most `threads` threads alive (2.6.0: one more).
- **Corrupt DNA literal chunk** returns `ACEAPEX_ERR_DATA` (2.6.0 returned orig_size with wrong bytes).
- **Library builds** (lzbench) no longer compile the CLI's stdin helper (`memfd_create`, glibc 2.27+).
- **AVX-512 rANS decoder** only with GCC 8+ / Clang 6+.
- **Fast streaming decoder**: header checked before the block table is allocated, 64-bit archive size on 32-bit
  builds, no `std::bad_alloc` through the C API.
- **Big-endian**: the fast profile (levels 11-18) runs on big-endian hosts and writes the same bytes as on x86 (qemu-s390x:
  round trips 56/56, archives identical). The default levels 1-3 support only little-endian hosts.
- Checked: HEAD judge (new claims `head_dna_err`, `head_dec_budget`), conformance 28/28, fast-profile tests and fuzz,
  ASan+UBSan round trips 77/77, 32-bit x86 (fast levels byte-identical to 64-bit; levels 1-3 identical to 32-bit 2.6.0),
  ARMv7 under qemu-arm 44/44, MinGW-w64 build. Logs: `results/rel261-*`.
