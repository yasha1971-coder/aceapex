# ACEAPEX 2.4.0 — DRAFT (date at tag time)

The FAST profile: the ACEPX2 container without an entropy stage. Independent 1 MiB blocks, a fixed-width token
stream, one decoder that is safe by construction, the same archive for the C++ library, the C99 decoder and the
Python package. Default-profile archives are unchanged byte for byte. Specification: `docs/FORMAT_FAST.md`.

## What changed

- Header version 3 under the same magic; `profile` and `min_match` in the header; `u64` block table; blocks of
  `u32` tokens (literal length 6 bits, match code 6 bits, distance 20 bits), extensions, literals, a 64-byte pad.
- Levels 11..18 (`--profile fast --level 1..8`): minimum match 16 / 12 / 8 / 5, greedy-lazy parse; 15..18 the same
  with an optimal parse. The minimum match is the level's one knob and it is read from the header.
- One decoder: exact-size buffers, the fast path only while a token fits in the output and the literal read lands in
  the pad; no second "unsafe" decoder. `scripts/fast_fuzz.cpp` (ASan/UBSan) in `make test` with a negative control.
- Readers: `aceapex_decompress[_mt]`, `_region`, `_ranges`, `_stream`, the CLI (`c`, `d`, `d --out -`, pipes, `r`,
  `faidx`), `axdec`, `libaceapex_decode.so`, `pip install aceapex`. Not in 2.4.0: GPU (`E_HEADER`),
  `aceapex_decode_streams` (`ACEAPEX_ERR_DATA`).
- Five new conformance fixtures (`verify/fixtures/conf/*_fast_*`), six new claims (`scripts/fast_test.sh`).

## Where it loses

- Ratio: silesia at min match 16 is 61 % of the input; the default profile is 32.6 %. Genomes: no DNA transform.
- Encoder: 25-28 MB/s on one core at levels 11-14, ~1 MB/s at 15-18 (TurboBench's rank weighs compression speed).
- GPU: not in 2.4.0.
