# CLAUDE.md — ACEAPEX (сессия ace-core)

ACEAPEX — параллельный блочный LZ77-компрессор с произвольным доступом, формат ACEPX2
(`docs/FORMAT_ACEPX2.md`), ниша — геномы. Декодеры: C++ (`src/`), C99 (`c/`), Python
(`python/`), GPU (`aceapex_gpu.cu`). Решения — `docs/DECISIONS.md` (ADR), релизы —
`CHANGELOG.md`, схема тегов — ADR-013 (софт `vX.Y.Z`, `vN.0`/`paperN-v1` — статьи, заморожены).

Отвечай по-русски, коротко, факты один раз. Стратегическое вето — только у Якова: факт или
риск называешь один раз, решение его. Одна задача за раз; при реальном сомнении — спросить,
а не угадывать.

Содержание правил (разделы 0–8) меняется только по слову Якова; по §9 сессия сама проводит лишь
механику — опечатки, ссылки, форматирование. Каждый документ — один владелец и одно место; файлы
`ACEAPEX/claude/` меняет только Claude.

## 0. Перед любой работой
1. Суть: какое решение изменится от результата. Нет решения — работу не начинать.
2. Потребитель: названный человек или проект с письменным запросом. Нет — это исследование без права на слова «ниша», «продаёт», «демо».
3. Кто решает лучше всех (ОБРАЗЕЦ): устройство кодека — Oodle (Kraken/Leviathan/Hydra); формат и выпуск — zstd/LZ4; для другой оси — её лидер с источником, например доставка пользователям — zxc (пакеты Debian/Ubuntu, Homebrew, vcpkg, Conan, winget; привязки Rust/Python/Node.js/Go/WASM; экспериментальный кодек ClickHouse `enable_zxc_codec`; источники: https://github.com/hellobertrand/zxc , https://clickhouse.com/docs/reference/statements/create/table/codec). Их механизм, их числа, наша разница (Prior Art Difference).
4. Прогноз — число из модели и вероятность (%), записанные в CALIBRATION до прогона.
   - Опора: модель строится на замере того же механизма (база S0, шаг счёта, потолок memcpy). Замера нет — сначала короткий замер базы, потом прогноз.
   - Потолок: до записи прогноз проверяется арифметикой против известных пределов (memcpy, число параллельных частей формата, прошлый замер той же машины).
   - Без прогноза прогон не начинается; если модель предсказывает ноль — прогон не нужен.
   - Каждые 20 прогнозов — счёт попаданий и Brier в CALIBRATION.

## 1. Измерение
- Судья — побайтное восстановление (sha256) + заранее записанный порог. Никаких оценок «на глаз».
- Эталон в каждом прогоне: silesia.tar = 211 947 520 Б (sha256 a667bac8…), enwik8; aceapex_fast,1 на silesia обязан дать ratio 61.57 % (130 490 328 / 211 947 520 Б, TurboBench). Не совпал — прогон недействителен.
- Сравнение — с лучшей альтернативой той же функции и всеми уровнями формата, который потребитель уже читает (урок sedpack: lz4hc).
- «В N раз» всегда с условиями: что сравнивается, вход, плотность, потоки обеих сторон, машина, число прогонов.
- Область вывода = измеренный диапазон. За ним — «не мерили».
- Срез, выбранный после результата, — гипотеза. Ниша — только после проверки на данных, не участвовавших в выборе.
- Подтверждённый ноль записывается как результат и закрывает направление в своей области.
- Байты основного профиля зависят от версии zstd: сверки по sha256 — только при одинаковой версии (выпуск = статический zstd 1.5.7).
- Судья на ace-core: `make test` = `./verify.sh HEAD` — свежий прогон, полный обязательный набор претензий из `verify/expected/HEAD.tsv`, 0 FAIL; `results/HEAD.json` не коммитить.

## 2. Метод (до основного прогона)
- Один шаблон долгого прогона: STATUS, сторож на зависание (60 мин), ожидание по PID, явный STOP, `trap ERR`. Не писать заново.
- Проверка метода на маленьком входе с известными ответами и отрицательным контролем на каждые ворота (каждые ворота обязаны уметь упасть).
- Проверка окружения в начале скрипта: зависимости, sha корпусов, компилятор, имена объектов.
- Поиск ошибок (аудит, поисковый фаззинг) — отдельно от ворот выпуска. Ворота — только на замороженном SHA.
- Результат судьи — только свежий: старые записи стираются до прогона, ненулевой код = FAIL.
- Красный прогон из-за ошибки метода — стоп и правка метода, не повтор в тот же день.

## 3. Код и формат
- Формат меняется только новой версией заголовка. fast v3 profile 1 заморожен.
- Декодер: никакого выделения памяти по полю архива без границы по реальным байтам/выводу; без указателей за пределы массива; любой входной размер проверяется против остатка.
- Молча неверный выход (успех + неверные байты) — ошибка высшего класса.
- Каждая найденная ошибка → детерминированный регрессионный вход в `verify/repro/` + претензия судье.
- Идеи чужих кодеков — только идеи, свой код (Oodle закрыт; lizard GPL).

## 4. Выпуск (контрольный фильтр, образец zstd/LZ4)
1. main = выпуск; TurboBench забирает main ежедневно — работа только в ветках.
2. Все ворота на одном SHA; правка — затронутые ворота заново с доказательством по diff.
3. Регрессионные входы — в репозитории.
4. Фаззинг всех входов декодеров с пределом выделения 64 MiB.
5. Открытые дефекты перечислены без подробностей способа, с версией исправления.
6. Сборка TurboBench (`make` и `STATIC=1`) и lzbench на кандидате.
7. Тег, Release, Zenodo и вливание в main кода/чисел/выпусков — только по слову Якова; выпуск не чаще раза в 2 недели, кроме исправлений.
- Новая работа — в отдельной ветке; в `main` — после свежего судьи 0 FAIL на ветке. В `main` само-merge — только документы без чисел и workflow, которые проверяет CI, после зелёного CI; код, числа, выпуски — по слову Якова.
- Ветка `release` = последний выпущенный тег (внешние подмодули, TurboBench); двигается только при выпуске — fast-forward на тег (`git push origin <тег>^{}:release`), иначе не трогать.

## 8. Code review и security review (без отдельных агентов)
Перед каждым коммитом кода кодека пройди сам:
- **Корректность:** все размеры из архива проверены против остатка входа и вывода; сумма — по одному слагаемому; нет UB (указатель до начала массива, переполнение знаковых); все пути ошибок возвращают код, а не `terminate`.
- **Совместимость:** архивы читает декодер последнего выпуска; уровни, которые не должны меняться, — побайтно равны прежним.
- **Безопасность:** входы декодера — недоверенные; выделение ограничено реальной потребностью; фаззер покрывает этот вход; регрессионный вход добавлен.
- **Производительность:** изменение скорости измерено на эталоне в том же прогоне; без прогноза — не заявлять.
